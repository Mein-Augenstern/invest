# PRD · invest 个人投资记账与纪律工具

> 章程见 [charter.md](charter.md)，业务规则见 [../business/overview.md](../business/overview.md)。
> **产品形态演进**：作者自用起步 → 分阶段对外开放（见 §6 开放路线）。

## 1. 产品定位

**面向个人投资者的记账与纪律工具**：以微信小程序为唯一用户端，覆盖基金/股票/债券/
理财五品类的记账、统计、估值与规则化纪律信号。定位是**"决策支持"而非"投资建议"**，
是**"纪律工具"而非"收益保证"**——这两句是产品的合规底线表述，开放后同样成立。

- **诞生方式**：作者本人是第一个用户与产品经理，所有功能先服务真实记账场景，
  再按开放路线逐步面向更多用户
- **核心差异化**：
  1. 口径自主——XIRR、月度盈亏等指标口径完全透明可控（竞品黑箱）
  2. 纪律信号——规则化评估（估值分位/缴存/再平衡），反对情绪化操作
  3. 数据主权——数据存放于运营者自有服务，不接入第三方广告/导流
- **替代关系**：券商 App 收益展示（口径被动）+ Excel 手工记账（无信号无移动端）

## 4. 非功能需求

- **安全**：密钥零内置、连接串/真实持仓不入公开仓；star JWT（HS256）网关+服务
  纵深防御；金额不进磁盘缓存（no-store）
- **可用性**：缓存秒开 + 401 自愈；首装配置引导；操作全部闭环于小程序（系统运维除外）
- **UI**：企业内部平台风（白卡细边框/主色 #1652a8/红涨绿跌），拒绝渐变/emoji/重阴影
- **质量门**：后端 pytest 全绿 + automator E2E 14 项全绿才允许提交推送

## 5. 明确不做（负面清单——开放后依然成立）

盘中实时估值 · 基金购买/筛选导购 · 社区/动态 · 券商自动下单 · PC 端 ·
收益预测承诺 · 投资咨询/荐股（监管需资质，永久不碰）。

## 6. 开放路线（自用 → 开放的三阶段）

> 原则：**每一阶段先满足准入条件再开放**；底线条款（§1 定位表述、§5 负面清单）
> 在所有阶段不变。现状为单用户系统，多用户改造是 O1 的准入条件而非既有能力。

### 阶段 O1 · 白名单邀请（亲友小规模）

- **准入条件**：
  - [ ] **数据隔离改造**：trades/instruments/diary/signals 等用户数据加 owner 维度
    （member_id），每用户独立账本与 portfolio（当前全局共享，是单用户假设的产物）
  - [ ] 公网化第二梯队完成（域名+HTTPS+云端部署）
  - [ ] 邀请机制：运营者后台添加白名单 member
- **规模**：≤ 20 人；**收费**：无

### 阶段 O2 · 公开发布（微信小程序正式版）

- **准入条件**：
  - [ ] 个体工商户/企业主体小程序认证 + 类目「工具-记账」（避开金融咨询类目）
  - [ ] **用户协议 + 隐私政策**页（微信上架硬性要求）：明示数据存储位置/用途、
    非投资建议免责声明
  - [ ] 个保法配套：账号注销能力、数据导出能力
  - [ ] 多租户运维配套：按用户配额/限流、备份恢复演练、监控告警
  - [ ] ICP 备案完成（域名与主体一致）
- **收费**：基础免费；付费能力（如高级报表）待定，**永不付费墙锁用户自己的数据**
  （导出永久免费）

### 阶段 O3 · 商业化探索（可选，未决）

方向候选：高级复盘报表 / 多账户组合 / 家庭共享版。约束：延续 §5 负面清单，
商业化只围绕"记账与复盘效率"，不向"投资建议"漂移。
