# 业务总览 · 记账/统计/信号/复盘

> 业务规则细节见 [strategy-rules.md](strategy-rules.md)，数据源与字段口径见
> [data-sources.md](data-sources.md)；本文讲**业务对象与业务流**。

## 1. 业务对象

| 对象 | 说明 | 载体 |
|------|------|------|
| 标的（instrument） | 五品类：`etf`/`open_end_fund`/`stock`/`bond`/`wealth`；yaml 种子 + DB 运行时合并 | instruments 表 + portfolio yaml |
| 流水（trade） | 动作：买入/卖出/分红/现金分红/**缴存(contribute)**；按金额或按份额录入 | trades.csv（源数据） |
| 时序（series） | 每标的×kind 的净值/价格/PE 历史（`etf_daily`/`fund_nav`/`stock_daily`/`bond_daily`/`manual_nav`/`pe_ttm_hist`） | series 表（幂等 upsert） |
| 信号（signal） | 规则评估产物：建议/已确认/已忽略 | signals 表 |
| 日记（diary） | 按日复盘 + 心情五标签（平静/贪婪/恐惧/犹豫/坚定） | diary 表 |
| 基金透视 | 定期报告持仓穿透 + 行业分布 | fund_holdings/fund_industry 表 |

## 2. 记账业务流

```
记一笔（表单/OCR 草稿确认）
  → 校验（超卖拒绝等，与 Web 端同源）
  → trades.csv 追加 → 报表按需重算
```

**核心口径（易错三连，前端格式化高频翻车点）**：

1. **contribute 只进现金流、不折算份额**——缴存是"入金"不是"买入"，曾误当卖出扣份额
   导致市值虚低 8000 元（真实对账抓出）
2. `xirr`/`unrealized_pct`/`drawdown` 是**小数**（0.05=5%，前端 ×100）；
   `benchmarks.pct_*` 已是**百分数**（95=95%，直接显示）
3. 月度盈亏 = Δ市值 − 净投入；年度账单中**账户现金单列**（存量累计，非单年）

## 3. 统计业务

- 总览：分组持仓市值、组合 XIRR（资金加权）、品类占比、养老金缴存进度（cap 12000/年）
- 统计页：资产总曲线（与月度统计同源 `_compute_mv`）、月度/年度收益、收益日历
  （单月逐日 pnl）、年度账单（最佳/最差月、已实现盈亏）

## 4. 信号业务流（纪律，不是预测）

```
规则书（估值分位定投 §1 / 年度缴存 §2.1 / 再平衡 §2.3）
  → evaluate_all：按标的品类取 series 指标 → 落区比对 → signals 落库（同日同标的同规则同动作去重）
  → 用户在信号页 确认/忽略；拉数完成后自动评估
```

信号措辞是"建议动作"（继续持有/加倍定投/触发再平衡检查），LLM 只做报告信息压缩，
**不做涨跌预测**（章程红线）。

## 5. 复盘业务

- **投资日记**：按日一记 + 心情标签——把"当时为什么买"留在可回查的地方
- **周报**：非 AI 生成（markdown 模板），可附 GLM 解读（信息压缩视角，无 Key 自动降级）
- **年度账单**：全年收益、月度盈亏、缴存完成度、最佳/最差月

## 6. 数据获取业务

- **拉数（pulljob）**：行情源四级兜底（东财→腾讯→新浪qfq→新浪不复权），逐标的拉取
  幂等入库，完成后自动信号评估；「我的」页可手动触发并看进度日志
- **截图识别（OCR）**：券商 App 截图 → macOS Vision 本地提文本（免费离线）→
  GLM 结构化为流水草稿（无 Key 降级返回原文，人工填）→ 确认入库；图片即用即删

## 7. 提醒业务（star 待办中心）

预设两条纪律提醒：**定投日·每月 10 号**、**缴存补缴检查·每年 11-15**——在「我的」页
选择家庭成员创建，经 star reminder 服务在其待办中心统一推送（标题 `[投资]` 前缀隔离）。
